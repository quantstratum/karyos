### Added

- The system clock to UTC half of the clock calibration (part of #749): `karyos-tools calibrate utc` turns one line of `chronyc -c tracking` (read from a file or standard input; the tool never runs chronyc) into a UTC reference record (ADR-0090) for the host's `CLOCK_REALTIME`: bound `|System time| + Root delay / 2 + Root dispersion + (Skew + |Residual freq| + maxclockerror) × window` rounded up to ns (chrony's own dispersion growth, `--max-clock-error-ppm` defaulting to chrony's 1 ppm), so it covers the whole validity window, source NTP, stepped UTC with leap table 72, valid from the sample time over a short window (`--window-ms`, at most 10 minutes), since the bound holds only as sampled. A missing field, an unsynchronised chrony (leap status "Not synchronised", stratum 0 or 16 and above) or a pending leap second prints no record. `karyos-tools calibrate realtime` (Linux) fits `CLOCK_MONOTONIC_RAW` to `CLOCK_REALTIME` from bracketed reads (`karyos_sys::host_clock::realtime_paired_read`), so a raw time reaches UTC through A10's combined bound; NTP slews `CLOCK_REALTIME`, so a run is short and a run no line explains is refused. Both print `record` lines that `calibrate append` journals. `calibrate compose <calibration>... <utc record>` composes the calibrations and refuses, with a typed error naming `--extension-ms`, a UTC record whose validity does not overlap theirs.
