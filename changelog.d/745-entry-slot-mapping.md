### Added

- The public mapping between the Cluster log's entries and the positions of the recording that holds them (R-CORE-8; karyos#745). `RaftLog::slot_of(index)` answers where an entry's frame is: an `EntrySlot`, which names the log epoch, position, length, index and term. `RaftLog::entry_at(epoch, position)` answers which entry starts there. `RaftLog::read_slot` reads an entry by its slot. Only entries both durable and committed are answered, since no leader can replace them. Each case with no answer is a value, never an error: `NotYet` past that stable prefix, `NotRecorded` below the index the log began at, `Purged` under retention, `BelowSnapshot` after an install (after later purges too), `NotAnEntry` inside a frame, and `OtherEpoch` for a slot an install cut. The log keeps its origin index and its last installed snapshot base in a new `log-origin` file. Slots survive a restart, and walking them from a first position replays the entries in the live order.
