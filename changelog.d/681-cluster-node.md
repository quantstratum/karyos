### Added

- The shipped Cluster node, `karyos_cluster::node::ClusterNode`, runs the custom Raft core (ADR-0105) as the shipped consensus behind `ConsensusCore`. That interface and its persist-then-send driver now live in `karyos_cluster::driver`, and the simulator re-exports them, so the harness and the shipped node share one interface. The node does not own a transport, and its caller supplies the clock. It refuses every message its driver releases before that message's data is durable. It compacts its log through the snapshot store and never purges across the Archive's hold (A2's purge floor). A follower behind the purge installs the leader's snapshot, and a restart resumes from the latest snapshot. Once warm, a steady request cycle allocates nothing: the node pools its command, reply and committed-entry buffers, and the host hands them back with `ClusterNode::buffer` and `ClusterNode::recycle`. `ServiceContainer::propose_with` and `Propose::propose_slice` propose without allocating (karyos#681).
