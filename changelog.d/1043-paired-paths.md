### Added

- Paired unicast paths are served (owner item 11, karyos#1043): a `paths=<interface>@<endpoint>;...` publication sends path `i` from its interface's address to its own endpoint over the routed sender, and a subscription receives path `i` at that endpoint, so one logical receiver gets each message once over every path and keeps receiving when one path fails. A publication path whose interface address this host does not have is refused at channel admission with the new `DriverError::UnknownInterface` (`UnsupportedChannel` on the client path); a path whose route to its endpoint leaves by another interface than the one owning its address, or two paths whose routes leave by one interface, are refused, and IPv6 paired paths are refused as unverifiable (no IPv6 route lookup); and where sockets cannot isolate paths (not Linux) paired paths stay refused with `UnsupportedChannel`. A path interface named by name is refused.
