### Added

- A caller-chosen operation id is used up by its first submit that is sent: a retry (same id, operation, driver, guard, principal and reason, with any token or none: `submit OPID - ...`) is answered with the retained outcome, unsent, an unknown outcome included, which is never retried as a new operation; the same id for anything else is `operation id conflict`; past 24 h, or from another boot, the id is a tombstone answered `operation expired`. Each sent submit is journalled as a new `Submitted` record (kind 19: its driver directory, full outcome and boot identity), and the outcomes and caller ids are rebuilt from those records at start, so a restart keeps them (R-CORE-18, karyos#738).
