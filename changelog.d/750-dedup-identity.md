### Changed

- The deduplication identity and retry contract (R-CORE-6b, karyos#750; decision X5): `SessionTable::request` takes the command, and a request is its exact `(client, epoch, sequence)` identity. A sequence past the next one applies, and the ones it skips are holes, not loss; a hole inside the window applies once when it arrives; the window spans `window` sequences from the acknowledged base, holes included, and an acknowledgement moves the base across sequences never submitted, so a gap wider than the window does not stall a session. A repeated identity with another command is the new `Outcome::PayloadMismatch` (each applied request keeps its command's length and CRC-32C), neither run nor answered as a duplicate. A retry keeps getting the outcome of its first apply even when the service would now refuse the same request, and a request of a gone session stays `SessionExpired` and opens nothing: a new epoch is only had by an explicit registration. A re-registered slot starts with an empty window. These rules come with the log: `SessionBounds` is now written as version 2 of schema 5, and a log whose bounds are version 1 (an earlier build's) replays the earlier contiguous rules (`SessionTable::exact`, `Outcome::OutOfOrder` for them only), so an upgraded replica never runs a command the original apply refused; an earlier build meeting version 2 bounds stops at that entry. The sessions section is version 2 of its encoding (the rules, holes and digests); version 1 still decodes, as the earlier rules. `SessionTable::decode_within` decodes under a byte budget, refusing before it allocates. Each window slot now reserves 8 more bytes of metadata: `DedupConfig::default()` reserves 33,623,040 bytes per replica, `DedupConfig::large()` 537,968,640.
