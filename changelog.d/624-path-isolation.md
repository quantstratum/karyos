### Added

- Multicast redundant paths on real sockets, on Linux (owner item 12, karyos#624). Every socket that joins a group sets `IP_MULTICAST_ALL` (`IPV6_MULTICAST_ALL` for IPv6) off, so a path socket bound to the wildcard address receives only the group it joined, on the interface it joined it on, never another path's datagrams. The Linux sockets backend therefore reports `isolates_paths`, and the driver admits a channel with `paths` instead of refusing it; macOS keeps refusing it, typed and counted, until an equivalent isolation test passes there. The call goes through `libc` in one safe wrapper of `karyos-io` (`linux_sys`), as the R8 record quantstratum-docs: karyos/reviews/dependency-admission-libc-linux-sockets.md admits. Unicast `paths` stay refused (karyos#1043).
- A channel whose redundant paths resolve to one interface (for example the unspecified address and the explicit address of the interface the group routes through) is refused and counted on Linux: both sockets would hold a membership on that interface, so one physical path would look like two (karyos#624). An IPv6 multicast join on a kernel without `IPV6_MULTICAST_ALL` (before Linux 4.20) keeps working, without the isolation; IPv6 `paths` stay refused.
