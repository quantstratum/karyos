### Added

- P5-S2, the standby scenarios S1 to S4, S6 and S7, now runs against the custom Raft core in both groups as well as the reference fixture, over the feed and over the Cluster log replication (`crates/karyos-sim/tests/standby_custom.rs`, karyos#713). Each group's leader is elected. Each standby check catches its violation planted in a record the core produced. `p5_s2_results_on_the_core_and_on_the_fixture` reports each scenario's result on the core and on the fixture apart, with its seeds. The fixture hands the primary's leadership to chosen servers twice; the custom core has no leadership transfer API, so on the core the same two leader changes are forced by crashing whichever primary server leads, and the test requires exactly two distinct changes with the standby following both with no gap and no duplicate. A leader-relative action (`Action::Leader`) now acts only on a primary server, never a standby one.
